Phase 2 — CSN Selection & Coverage

Triggered after product selected. Seller searches and selects which CSNs to cover. Hierarchy rules apply.

flowchart LR A([← From Phase 1]) --> B[Search CSNs by\nemail, name, location] B --> C{Eligible CSNs\nfound?} C -- Yes --> D["Select CSNs for coverage\n━━━━━━━━━━━━━━━━\nL1 → all L2+L3 auto-selected\nL2 → all L3 auto-selected\nOnly L3 allows deselect"] C -- No --> X([Customer not eligible\n— EXIT]) D --> E{CSNs in same\nhierarchy?} E -- Yes --> F[Validate eligible\nsubscriptions] E -- No --> Y([Reject — cross-hierarchy\nnot allowed]) F --> G([→ Go to Phase 3:\nAOV & Pricing]) style A fill:#1a73e8,color:#fff,stroke:none style G fill:#34a853,color:#fff,stroke:none style X fill:#ea4335,color:#fff,stroke:none style Y fill:#ea4335,color:#fff,stroke:none style C fill:#fff3cd,stroke:#e6a817 style E fill:#fff3cd,stroke:#e6a817 style D fill:#e6f4ea,stroke:#34a853
Hierarchy rule: If an L2 or L1 has already purchased a Business Plan and a user tries to add an L3-level CSN, the system throws an error. At L3 level, if BP is already purchased, those CSNs are excluded from L1/L2 purchase flows.

Phase 3 — AOV & Pricing on Opportunity

System auto-calculates AOV from Finmart/EDH. ADV is system-populated and non-editable. Seller enters scope fields.

flowchart LR A([← From Phase 2]) --> B["AOV auto-calculated\n(Finmart/EDH trailing 12mo)\n→ ADV system-populated\n⚠ Non-editable"] NF["New customer fallback:\nNo trailing 12mo spend?\n→ Use current deal value\nas AOV input"] -.->|fallback| B B --> C[Enter Scope of Use\n& Scope Details\nADV locked] C --> D{Validation\npasses?} D -- Yes --> E[O2P returns Extended Price\nValue Tier · Value Factor] D -- "No — ADV=0 or\nfields missing" --> F[Fix validation errors] F --> B E --> G[Save OLI to Opportunity] G --> H([→ Go to Phase 4:\nPricing Approval]) style A fill:#1a73e8,color:#fff,stroke:none style H fill:#34a853,color:#fff,stroke:none style D fill:#fff3cd,stroke:#e6a817 style B fill:#e8f0fe,stroke:#1a73e8,font-weight:bold style NF fill:#fffbea,stroke:#f0c040 style F fill:#fce8e6,stroke:#ea4335
Key rule: ADV is system-controlled and non-editable once calculated. OLI Qty = 1, locked. Price lock prevents manual modification after AOV is set. AOV recalculates whenever CSN selection changes.

Phase 5 — Quote & Order

Create quote, validate line items, submit order via CPQ, Pelican confirms and entitlements are granted.

flowchart LR A([← From Phase 4]) --> B[Create Quote\nfrom Opportunity] B --> C[CPQ populates VBP\nattrs as read-only] C --> D{VBP line item\nparity valid?} D -- No --> E[Fix line item mismatch] E --> B D -- Yes --> F[Finalize and send Quote] F --> G{Customer\naccepts quote?} G -- No --> H[Revise or\nabandon opportunity] G -- Yes --> I[Submit Order\nvia CPQ] I --> J[Order confirmed\nby Pelican] J --> K[Closed-loop:\nOLI = Completed\nSub ID populated] K --> L[CSN coverage associations\ncreated — Pelican] L --> M[Entitlement platform\ngrants BP-level benefits\nto covered CSNs] M --> N([→ Go to Phase 6:\nRenewal]) style A fill:#1a73e8,color:#fff,stroke:none style N fill:#34a853,color:#fff,stroke:none style H fill:#ea4335,color:#fff,stroke:none style D fill:#fff3cd,stroke:#e6a817 style G fill:#fff3cd,stroke:#e6a817 style L fill:#e6f4ea,stroke:#34a853 style M fill:#e6f4ea,stroke:#34a853
Closed-loop: After Pelican confirms, CSN coverage associations are created and the entitlement platform reads those associations to grant BP-level benefits — subscriptions are NOT mutated. Service Plan Code remains Standard.

Phase 6 — Renewal Workflow

System generates renewal opportunity. AOV recalculates from current spend. Seller can add/remove CSNs before submitting.

flowchart LR A([← From Phase 5]) --> B[System generates Sub Oppty\nwith renewal line items] B --> C[Renewal Rep opens\nreconfigure screen] C --> D[ADV defaults\nfrom prior term] D --> E[System recalculates AOV\nfor covered CSNs\nFinmart/EDH trailing 12mo] E --> F[Renewal Rep updates\nADV if needed] F --> G[Enter Scope fields\nnull on renewal] G --> H{Modify CSN\ncoverage?} H -- Yes --> I[Add or remove CSNs\nAOV recalculated] I --> J[Save and Create Quote] H -- No --> J J --> K[Submit Renewal Order] K --> L["Closed-loop: OLI = Renewed\nCSN coverage associations updated\nEntitlements refreshed"] style A fill:#1a73e8,color:#fff,stroke:none style L fill:#34a853,color:#fff,stroke:none style H fill:#fff3cd,stroke:#e6a817 style L fill:#e6f4ea,stroke:#34a853
Renewal rules: A new L3 CSN created under a covered L2 during the prior term is NOT automatically added at renewal — seller must manually add it via Manage Covered CSNs. Tier may increase or decrease based on new AOV.

Phase 7 — Amendments (Mid-Term CSN Additions)

Seller can add CSNs to an active Business Plan during the term. No extra charge now — uplift applies at renewal.

flowchart LR A([AE opens active\nBusiness Plan]) --> B[Search & select\nadditional CSNs to add] B --> C{Same account\nhierarchy?} C -- No --> X([Error: cross-hierarchy\nnot allowed — blocked]) C -- Yes --> D[AOV recalculated\nwith added CSNs] D --> E[OLI updated\nNo extra charge now\nUplift at renewal] E --> F([Amendment saved\nCoverage list updated]) style A fill:#1a73e8,color:#fff,stroke:none style F fill:#34a853,color:#fff,stroke:none style X fill:#ea4335,color:#fff,stroke:none style C fill:#fff3cd,stroke:#e6a817 style E fill:#e6f4ea,stroke:#34a853
Mid-term amendment rules: Hierarchy validation is mandatory. No additional charge during active term — added CSNs are captured in spend at renewal. Eliminates the legacy true-up model.

System: Auto-Coverage for New Subscriptions

Fully automated — no seller action required when a new subscription is purchased under an already-covered CSN.

flowchart LR A([New sub purchased\nunder covered CSN]) --> B[System detects CSN\nin coverage association list] B --> C[Entitlement platform\nauto-grants BP-level benefits] C --> D["No seller action\nNo price change\nNo sub mutation\nService Plan Code = Standard"] D --> E[Renewal forecast updated\nwith new sub spend] style A fill:#1a73e8,color:#fff,stroke:none style E fill:#34a853,color:#fff,stroke:none style C fill:#e6f4ea,stroke:#34a853 style D fill:#e6f4ea,stroke:#34a853
Auto-coverage rules: Only works for CSNs already in the coverage list. No AOV recalculation or renewal trigger at point of auto-coverage. New subscription spend is captured at next renewal.

New CSN During Term — No Auto-Expansion

A new L3 CSN created under a covered L2 during the term does NOT automatically get BP coverage.

flowchart LR A([New L3 CSN created\nunder covered L2]) --> B[NOT auto-added\nto BP coverage list] B --> C[New subs get\nStandard support only\nNo BP benefits] C --> D{Needs immediate\ncoverage?} D -- Yes --> E[Manual support request\nor buy under\nalready-covered CSN] D -- "No — wait for renewal" --> F[Add CSN at renewal\nvia Manage Covered CSNs] style A fill:#e67e22,color:#fff,stroke:none style B fill:#fce8e6,stroke:#ea4335 style C fill:#fce8e6,stroke:#ea4335 style D fill:#fff3cd,stroke:#e6a817 style E fill:#e8f0fe,stroke:#1a73e8 style F fill:#e6f4ea,stroke:#34a853
Key policy: Auto-coverage is per the CSN list at purchase time — NOT per the hierarchy. A new L3 under a covered L2 is not automatically covered. The only path to immediate coverage is a manual support request. Standard addition path is at renewal.
